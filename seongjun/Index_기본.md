인덱스의 기본 구조와 탐색 원리

인덱스 탐색과정은 수직, 수평 두 단계만 있다.

DB 테이블에서 데이터를 찾는 방법도 2가지뿐이다.

- 테이블 전체를 스캔한다.
- 인덱스를 이용한다.

인덱스 튜닝의 두 가지 핵심요소

큰 테이블에서 소량 데이터를 검색할 때 사용한다.

인덱스 튜닝 방법은 2가지가 있다.

1. 인덱스 스캔 효율화 튜닝
2. 테이블 액세서 횟수를 줄이는 것(액세스할 때 랜덤I/O방식을 사용 ⇒ 이를 랜덤 액세스 최소화 튜닝)

SQL 튜닝의 핵심은 랜덤 I/O와의 전쟁이다.

⇒ db성능이 느린 이유는 디스크 I/O 때문이다.

조인 메서드 중 가장 일반적으로 사용하는 NL조인이 대량 데이터를 조인할 때 느린 이유도 랜덤 I/O때문이다. 그래서 느린 랜덤 I/O을 극복하기 위해 조인 메서드가 개발된 기능이다.

### 인덱스 구조

DB에서도 인덱스 없이 데이터를 검색하면, 테이블을 처음부터 끝까지 모두 읽어야 한다.

반면, 인덱스를 이용하면 일부만 읽고 멈출 수 있따.

즉, 범위 스캔이 가능하다 ⇒ 인덱스가 정렬돼 있기 때문이다.

DBMS는 일반적으로 B*Tree 인덱스를 사용한다.
